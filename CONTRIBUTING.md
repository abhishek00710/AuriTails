# Contributing to AuriTails

Thanks for contributing.

## Workflow

1. Create a feature branch from your default branch.
2. Keep changes focused and easy to review.
3. Run a local build in Xcode before opening a pull request.
4. Include screenshots or a short screen recording for visible UI changes.
5. Mention any simulator, signing, or environment limitations in the PR description.

## Code Style

- Follow the existing SwiftUI style in the project.
- Prefer small reusable views over very large single-file view bodies.
- Keep comments short and only where they clarify non-obvious intent.

## Pull Requests

Please include:

- What changed
- Why it changed
- How it was tested
- Any known follow-up work

## Scope Notes

AuriTails currently favors polish and product direction over persistence or backend integration. If you add infrastructure work, keep the user-facing experience clean and coherent.
